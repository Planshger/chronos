# Chronos

Chronos — клиентское веб-приложение для планирования дел. В приложении есть календарь задач, регистрация и вход, тарифы, пользовательские настройки, связь с Telegram и административный раздел для работы с пользователями и тарифами. Поддерживаются роли пользователя (`user`) и администратора (`admin`).

## Требования

- Node.js (рекомендуется актуальная LTS-версия)
- npm

## Установка и запуск

Из корня проекта выполните:

```bash
npm ci
cp .env.example .env
npm start
```

Адрес API задаётся в `.env` через `REACT_APP_API_BASE_URL`.

Приложение откроется по адресу [http://localhost:3000](http://localhost:3000). Сервер разработки обновляет страницу при изменении исходников.

## Форматирование

Для форматирования используется Prettier.


## Что делает приложение

- **Главная (`/`)** — описание продукта и переходы к регистрации, тарифам или рабочему разделу.
- **Регистрация и вход (`/register`)** — создание аккаунта пользователя, вход пользователя или администратора.
- **Тарифы (`/plans`)** — список активных тарифов. Вошедший пользователь может выбрать тариф; выбор сохраняется через API и активирует аккаунт.
- **Расписание (`/schedule`)** — календарь и создание, изменение и удаление задач по датам. Доступно пользователям с ролью `user`.
- **Настройки (`/settings/...`)** — пользователям доступны профиль, тариф, аналитика, Telegram и карта; администраторам — профиль и управление тарифами. Аналитика показывает демонстрационные значения, карта обозначена как «В разработке».
- **Админ-панель (`/admin`)** — таблица пользователей с пагинацией, поиском, сортировкой, фильтрами и редактированием данных.
- **Telegram** — экран настроек показывает ссылку и QR-код для привязки аккаунта. После привязки доступен чат: приложение загружает до 10 последних сообщений и опрашивает API каждые 3 секунды, пока открыт чат.

Некоторые элементы интерфейса пока являются заглушками: ИИ-ассистент не отправляет запросы, действия бронирования такси/отеля/столика не реализованы, а карта помечена «В разработке». В настройках тарифа кнопка продления пока не подключена; отображаемая дата окончания подписки задана статически.

Настройки WhatsApp в текущей навигации не доступны. Реализация компонента-заглушки есть в коде, но маршрут и пункт меню для него не настроены.

## Архитектура

Проект создан на React, TypeScript и Create React App. `src/index.tsx` — точка входа: она подключает провайдер ошибок, создаёт и предоставляет MobX-сторы, затем монтирует приложение. `src/App.tsx` настраивает тему Material UI, маршруты и ограничения доступа.

Основные каталоги `src`:

```text
src/
  index.tsx                точка входа, провайдеры и инициализация сторов
  App.tsx                  тема, маршруты и ограничения доступа
  app/
    routes/                защита маршрутов по авторизации и роли
    stores/                создание сторов и связь авторизации с расписанием
  pages/                   тонкие компоненты страниц для маршрутов
  modules/                 функциональные модули: admin, auth, landing,
                           plans, registration, schedule и settings
    index.ts               публичная точка входа модулей и их API
    <module>/
      components/          UI-компоненты конкретного модуля
      datasources/         API-операции, используемые модулем
      models/              модели и типы конкретного модуля
      stores/               состояние модуля, если оно ему нужно
  shared/                  общее API, ошибки, UI, тема, модели и утилиты
```

Компоненты в `src/pages` служат адаптерами между маршрутизацией и функциональными модулями. Например, `src/pages/admin/Admin.tsx` отображает `AdminModule` из модуля `admin`. Основная реализация страниц и компонентов находится в `src/modules`.

`src/modules/index.ts` — публичная точка входа для экспортируемых компонентов, типов и операций модулей. Страницы импортируют модули через неё:

```ts
import { AdminModule, getAllUsers } from './modules';
```

При добавлении публичного компонента, типа или операции модуля экспорт добавляется в `src/modules/index.ts`. Внутри модулей связанные компоненты, datasource-функции, модели и сторы импортируются напрямую. Общие модели и утилиты находятся в `src/shared`; специфичные для модуля — внутри каталога этого модуля.

Защищённые маршруты используют роль пользователя: расписание — `user`, админ-панель — `admin`, общие настройки доступны обеим ролям. Авторизацией управляет `AuthStore`: токен сохраняется в `localStorage` под ключом `token`, а при восстановлении сессии стор проверяет текущего пользователя через API.

### Управление состоянием с MobX

MobX используется для общего состояния авторизации и расписания:

- `AuthStore` (`src/modules/auth/stores/AuthStore.ts`) хранит токен, текущего пользователя и состояние проверки авторизации. Он восстанавливает пользователя по сохранённому токену, обновляет состояние при входе и выходе и обрабатывает заблокированный аккаунт.
- `ScheduleStore` (`src/modules/schedule/stores/ScheduleStore.ts`) хранит задачи, выбранную дату и месяц, состояние модальных окон и загрузки. Операции загрузки, создания, изменения и удаления задач выполняются через datasource расписания.

Оба стора создаются в `src/app/stores/AppStores.ts` и передаются компонентам через `Provider` из `mobx-react` в `src/index.tsx`. Там же `initializeStores` связывает авторизацию с расписанием: MobX `reaction` следит за ID пользователя и задаёт ID в `ScheduleStore` для вошедшего пользователя с ролью `user`. После этого хранилище загружает его задачи. Компоненты, которым нужны сторы, подключаются через `injectMobxStore` (`src/shared/utils/injectMobxStore.ts`), который объединяет `inject` и `observer`, чтобы компонент получал стор и реагировал на изменения наблюдаемого состояния.

### TanStack Query

В проект добавлен TanStack Query (`@tanstack/react-query` v5). Общий `QueryClient` создаётся в `src/shared/queryClient.ts` и подключается через `QueryClientProvider` в `src/index.tsx`.

Пока что он используется непосредственно в datasource-функциях через `queryClient.fetchQuery` для получения данных авторизованного пользователя, списка тарифов и одной из выборок пользователей с пагинацией; для этих запросов задаются `queryKey`. Остальные запросы выполняются через `apiRequest` без TanStack Query. Опрос сообщений Telegram реализован отдельно через `setInterval`.

## Сервер и сетевые запросы

Базовый адрес API задаётся в `.env`:

```text
REACT_APP_API_BASE_URL=https://278465bc4840a875.mokky.dev
```

Для новых окружений скопируйте `.env.example` в `.env` и укажите нужный адрес. Браузер отправляет запросы непосредственно к этому серверу; поэтому сервер должен разрешать запросы с домена приложения (CORS).

Общая функция `apiRequest<T>()` находится в `src/shared/api/apiRequest.ts`. Она добавляет стандартный заголовок `Accept`, выставляет `Content-Type: application/json` для строкового тела запроса, проверяет HTTP-статус и разбирает JSON-ответ. Ответы `204 No Content` и пустые ответы на `DELETE` считаются успешными; прочий пустой ответ и некорректный JSON считаются ошибками.

### Обработка ошибок

`ApiErrorStore` входит в общий набор MobX-сторов, создаваемых в `src/app/stores/AppStores.ts`. Компоненты получают `showError` через `useApiError`, а `AuthStore` и `ScheduleStore` — при создании. `ApiErrorSnackbar` наблюдает за состоянием стора и показывает пользовательское сообщение в закрываемом Snackbar с типом `error` на 6 секунд.

Неизвестные URL обрабатываются маршрутом `*` и показывают страницу 404. Ошибки рендеринга интерфейса перехватывает `ErrorBoundary`; в этом случае пользователю предлагается перезагрузить страницу.

В `src/shared/errors/AppError.ts` определены ошибки, для которых показываются отдельные сообщения:

- `NetworkError` — не удалось связаться с сервером или прочитать тело ответа.
- `HttpError` — сервер ответил неуспешным HTTP-статусом. Для статусов `5xx` показывается сообщение о сбое сервера; для остальных — об ошибке выполнения запроса.
- `EmptyResponseError` — успешный ответ оказался неожиданно пустым.
- `ResponseParseError` — тело ответа не удалось разобрать как JSON.
- `InvalidCredentialsError` — неверная почта или пароль. В datasource авторизации HTTP `401` преобразуется в эту ошибку.
- `BlockedUserError` — аккаунт заблокирован. `AuthStore` передаёт ошибку в глобальный обработчик, показывает сообщение в Snackbar и завершает сессию.

Для неизвестных ошибок, которые не являются `AppError`, показывается общее сообщение: «Произошла непредвиденная ошибка. Попробуйте ещё раз». Техническая информация и исходная ошибка хранятся в объекте ошибки во время обработки, но провайдер не записывает их в консоль, сервер или постоянный журнал. Запросы, отменённые с `AbortError`, не преобразуются в `NetworkError`; если такую ошибку передать в `showError`, она отобразится как непредвиденная.

Функции предметных операций расположены в datasource-файлах модулей и используют обёртку. Например:

```ts
export function getAllUsers(): Promise<UserModel[]> {
  return apiRequest<UserModel[]>('/users');
}
```

Новый API-вызов следует добавлять в datasource соответствующего модуля и выполнять через `apiRequest`, чтобы общая обработка ответов и ошибок оставалась единообразной.

Чат Telegram загружает сообщения при открытии и далее опрашивает сервер каждые 3 секунды, пока чат открыт. Опрос реализован в компоненте чата, а не средствами TanStack Query.
